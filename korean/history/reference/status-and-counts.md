## ‘완료’라는 말의 목적어

| 표현 | 실제 뜻 | 구분할 상태·범위 |
|---|---|---|
| packet 생성·전달 | 입력이 준비된 상태입니다. | 실제 판독·제출은 이후의 기록에서 확인합니다. |
| 공식 판독 제출 | 결정의 범위·인용·형식과 상태가 저장됐습니다. | 제출 상태와 후속 검토 상태를 구분합니다. |
| verified | 당시 렌더·기하 검증 조건을 통과했습니다. | 사람의 승인 여부는 별도 상태입니다. |
| local_completed | 독립 작업 공간에서 대상 처리를 마쳤습니다. | 원천 DB의 보류 해제·병합 여부는 별도로 확인합니다. |
| human_approved=false | 사람 승인이 기록되지 않았습니다. | 기계 실패나 모든 페이지의 미열람을 뜻하는 상태는 아닙니다. |
| 승인 필드 없음 | 해당 필드가 없습니다. | false 또는 true로 임의 변환하지 않습니다. |
| integration/merge receipt | 수신 측에 실제 반영됐습니다. | 생산자의 과거 상태 문서를 소급 수정한 것은 아닙니다. |
| output 집합 일치 | 지정 대상 출력의 구조·커버리지가 일치합니다. | 이 검사의 대상은 지정한 출력 집합입니다. |

## 해결하거나 남겨 둔 충돌

- 사용자 요청의 ‘13개’와 실제 note 14개: 새로 분석한 13개와 기존 연락처 note 1개입니다. 관리 기록으로 차이를 확인했습니다.
- 복사 manifest의 81,835행과 README의 81,836행: 관측 차이를 유지합니다. 헤더 때문이라는 추측을 사실로 쓰지 않았습니다.
- P0 계획의 70,424쪽과 관측된 70,423쪽: 해당 초기 실험에서는 별도의 미해결 gate였습니다. 최종 66,010쪽으로 숫자를 덮지 않았습니다.
- game에는 전체 새 OCR 실행이 없고 final에는 있는 상태: 시점과 작업 위치가 다릅니다. 앞선 계획을 후속 실행과 연결했습니다.
- 생산자의 미병합 상태와 후속 수신 통합: 시점 차이입니다. 수신 영수증을 추가로 연결했습니다.
- 최신 final_verification이라는 파일명과 1,893쪽 부분집합인 본문: 최초 전체 보고는 before 보관본으로 추적했습니다.
- 오래된 partial 물리 파일과 현재 manifest의 partial 0: 파일 존재와 현재 선택 상태를 구분했습니다.
- read-v2/read-next 제작 보고의 미시작 상태와 후속 제출: 보관 DB·session·영수증으로 제작 이후의 실행을 추가했습니다.
- tri-force-gumsu memory의 초기 조사 미완료와 저장된 최종 보고: 후속 AUDIT_COMPLETE와 summary로 조사 결과를 보강했습니다.
