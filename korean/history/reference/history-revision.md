## history-anchor-v1 — 추가 조사

v1의 조사 기준일은 2026-09-26입니다. 기존 13개 신규 folder note와 연락처 note를 출발점으로 삼고, Documents의 폴더 구조와 연결된 보관본을 추가로 조사했습니다. 첫 탐색은 숨김 폴더·의존성 디렉터리를 제외한 3단계 디렉터리 색인, 후속 조사는 관련 폴더의 문서·코드·DB·영수증·ZIP 내부 파일을 대상으로 했습니다. 사건과 연결된 자료를 후속 조사의 대상으로 삼았습니다.

### 발견했지만 새 사건으로 넣지 않은 자료

- 기존 웹 서비스·아카이브 앱, 초기 정리 폴더: 구성과 파일 이름만으로 현재 처리 사건의 직접 원인·수신 연결을 만들지 않았습니다.
- kgu-part: 학과 사전의 독립 자료·소비 계약은 있으나 이번 핵심 전환에 새 인과 연결을 추가하지 않았습니다.
- OCR JSON 복사본과 이미지 열람용 사본: 별도 보관·검토 입력이라는 역할을 확인했고, 새 마스킹 성과로 세지 않았습니다.
- voku-arc-publishing, voku-chat-context, safe-context, holdon, written 및 다른 공개 초안: 계획·미러·재구성 문서는 원 실행 기록을 찾는 색인으로 사용했습니다. 후대의 정돈된 구조를 당시 운영 방식으로 가져오지 않았습니다.
- call 아래의 canary 패키지와 여러 이전 ZIP: 관련 경로를 확인했으나 현재 사건을 보강하는 실행·수신 연결이 확보된 자료만 본문에 채택했습니다. ZIP은 필요한 DB와 checkpoint를 읽고 기존 파일은 이동·정리하지 않았습니다.

### 인과관계를 확장하지 않은 지점

52쪽 시험의 판독 시간과 뒤의 사용자 시간 최적화 요구는 각각 확인됩니다. 그러나 그 측정 하나가 후자의 직접 원인이라고 명시된 기록은 없습니다. blind pilot의 응답 부재를 이후 모든 이미지 판독을 포기한 원인으로 연결하는 기록도 없습니다. read-v2/read-next의 의미 있는 구현·실행을 보존하되 두 패키지가 주 처리로 통째로 흡수됐다고 쓰지 않았습니다.

### v1에서 보존한 범위

v1은 HISTORY, 여섯 사례, 연결된 근거·집계·역사 코드의 SHA-256을 고정했습니다. 당시 편집에서는 WORKFLOW.md에서 사용자가 지정한 문장만 제거했습니다. 기존 공개본은 비공개 조사 공간에 보관했습니다.

## history-anchor-v2 — History 영역 정리

2026-09-26의 후속 요청에 따라 History를 이후 작업의 기준점으로 정리했습니다. 기존 본문의 여섯 시기, 세부 연표, 실패·중단 경로와 여섯 사례를 유지했습니다.

- 루트의 HISTORY.md를 `history/HISTORY.md`로, WORKFLOW.md를 `history/evolution.md`로 옮겼습니다. cases·reference·historical도 같은 History 영역으로 옮겼습니다.
- History의 입구인 README, 초반 용어표와 전체 문제 분기·합류 지도를 추가했습니다. read-v2/read-next의 분기와 합류가 확인된 결과를 구분했습니다.
- 숫자 연도와 Unknown을 합한 초기 처리 범위를 처음 설명하는 곳에 분모를 보강했습니다.
- reference는 수치와 내용상의 판단을 유지하며 띄어쓰기·조사·명칭·표 문장과 메모형 서술을 다듬었습니다. 일반적인 면책 문장은 정리하고, 미실행·미병합·중단·시점 차이를 설명하는 문장은 남겼습니다.
- 기존 demo와 데모용 루트 의존성 목록을 제거했습니다. workflow와 demo에는 내용이 없는 `.gitkeep`만 두어 Git에서도 디렉터리가 유지되게 했고, 루트 README는 세 영역으로 가는 입구로 바꿨습니다.
- historical의 코드 파일과 기존 비식별 집계·코드 provenance는 내용을 바꾸지 않고 옮겼습니다. 내부 링크, 공개 허용 목록, 검사기의 경로를 새 구조에 맞췄습니다.

## history-anchor-v3 — 국소 편집

이전 공개초안의 데모 검증·재사용 설명을 제거하고, History 패키지 밖으로 향하던 링크는 본문을 유지한 채 해제했습니다. 내부 코드명은 본문에서 처음 등장할 때 기능명을 병기했으며, HISTORY·evolution·여섯 사례의 서술 어미를 평서체로 통일했습니다.

상세 관계도와 `limits.md`, 역사 코드와 집계 JSON은 보존했습니다. 본문·사례의 문단·표·절 구성과 수치, 시제·인과관계·판단 강도를 유지하며 국소 편집했습니다.

## history-anchor-v4 — 실물 사진과 공개 안내

History 진입점과 라이선스 안내를 갱신했습니다. 작성자의 지시에 따라 보존 코드를 포함한 공개 자료에는 MIT-0을 적용합니다. 과거 코드 13개, 근거·집계 JSON, 여섯 사례와 처리 방식의 변화는 그대로입니다. 이번 편집의 확인 결과는 [공개본 검증 기록](publication-check.md)에 남겼습니다.

## 기준본 사용

원본 기준본은 **history-anchor-v6 · 2026-09-27**입니다. 2026-09-26 조사·재배치로 정리한 v3 처리 서사를 유지하고, 실물 사진과 공개 안내를 더했습니다. 개별 사진은 원본 구도를 유지하며 대표 스트립은 운반·보관 장면을 중심으로 조정했습니다. 당시 기준본에서는 설명 문서의 어미를 존댓말로 통일했습니다. 현재 영어 기본 배포본의 버전은 manifest에서 별도로 구분합니다.

[HISTORY](../HISTORY.md), [evolution](../evolution.md), 여섯 사례, 연결된 근거·집계·검증 기록·역사 코드를 [anchor manifest](../../../history/history-anchor.json)의 SHA-256으로 고정합니다. manifest의 경로는 repository 루트를 기준으로 합니다. 이후 workflow와 demo에서 이 기준본을 인용하며, 새 기록으로 History 자체를 고칠 때는 변경 근거를 남기고 버전을 올립니다.
