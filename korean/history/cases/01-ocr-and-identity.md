# 1. OCR 복구와 신원 재구성은 같은 성공이 아니었습니다

[English](../../../history/cases/01-ocr-and-identity.md)

[History](../HISTORY.md) · [판독 운영의 전환](02-reading-and-state.md)

## 초기 가정과 사람 검토가 드러낸 문제

초기 개인정보 처리 계획 (P0-4.5)은 이름을 우선으로 하면서 학번·학과·결재란까지 다루려 했습니다. 비공개 명단을 만들고 넓게 후보를 모아 사람이 판정한 뒤 이미지에 적용하는 구상이었습니다. 이것은 후대의 **이름만 처리하는 1차 패키지**와 범위가 다릅니다. [E01](../reference/evidence.md#e01)

2026-08-24의 513건 사람 검토 분석에는 이름 입력 151건, 이름 정정 131건이 기록되어 있습니다. 정정 131건 중 61건은 기존 두 OCR 중 하나에 이미 존재했고 70건은 양쪽 모두 놓쳤습니다. 기계가 보류했던 108건이 사람 판단에서는 마스킹 대상으로 바뀌었습니다. 후보가 보이는가, 글자가 맞는가, 누구인가, 어디까지 지우는가는 서로 다른 실패였습니다. [E04](../reference/evidence.md#e04)

원래 검토 ledger에는 일반 비스태프 사람을 뜻하는 메모가 `PUBLIC_PERSON_EXCLUDE`와 함께 남은 경우도 있었습니다. 형식상 유효한 상태가 의도한 보호 범위를 제대로 표현하지 못했습니다. 이를 단순히 사람 정답으로 덮어쓰지 않고 분류 축을 다시 나누는 문제가 되었습니다.

## 더 나은 OCR이 바로 더 많은 후보를 뜻하지 않았습니다

| 제한된 실험 | 실제 결과 | 다음 판단에 남긴 것 |
|---|---|---|
| 인쇄체 알려진 실패 13건 재OCR | 정확 7 / 부분 4 / 미복구 2 / 확신한 오답 0 | 복구 표기를 기존 관측에 추가할 근거 |
| 손글씨·혼합 56건 재OCR | 정확 22 / 부분 11 / 미복구 14 / 확신한 오답 9 | 오답과 미복구를 따로 남긴 제한 override 자료 |
| 복구 OCR을 기존 513건 평가에 추가 | 기존 대상 440/440 보존, 새로 보인 대상 0, 기존 ID 재작성 0 | 표기 개선과 후보 노출을 분리해 평가; 남은 HOLD 노출 문제 유지 |

새 표기는 기존 observation에 **추가 증거**로 붙었습니다. 기존 Rough/Fresh OCR을 지우지 않았습니다. 이미 후보를 회수하던 평가에서 표기 품질과 근거가 좋아진 것을 후보 수 증가로 세지 않았고, 남은 HOLD 17건의 검토 노출 문제는 별도였습니다. 이 실험 시점에는 전체 후보 생성과 이미지 마스킹을 시작하지 않았습니다. [E05](../reference/evidence.md#e05)

## 기술 실험과 별도로 남은 도구 사용 사고

손글씨 실험 중 로컬 이미지 판독 경로가 네 사례의 crop을 묶은 몽타주를 외부 저장소로 전송한 사실이 발견됐습니다. 해당 경로를 중단하고 로컬 고정 근거를 사용하는 방식으로 돌아갔습니다. [E05](../reference/evidence.md#e05)

## 큰 신원 모델을 실제 돌렸지만, 그것도 이미지 완료는 아니었습니다

대규모 신원 재구성 (P0-4.5v2 attempt 008)은 숫자 연도 66,010쪽·5,330문서와 Unknown 4,413쪽·389문서를 합한 70,423쪽·5,719문서 범위의 재구성을 실행했습니다. 같은 이름의 모든 조합을 만드는 대신 자격을 만족한 근거 사이만 연결했습니다. 불완전한 조합 598,223개는 집계로 남기고 개별 관계로 펼치지 않았습니다. 로컬 소속이 해결되지 않은 1,311개 probable occurrence도 재분류했습니다. [실제 코드](../../../history/historical/identity/global_identity_v3.py), [E06](../reference/evidence.md#e06)

후보 의미 구조 수리 (attempt 009)에서는 구조화한 이름 칸·소속·학적·신원 가설을 분리했습니다. 중간 QA가 `UNRESOLVED_BINDING` 16건을 `NOT_STATED`로 표시한 실패를 수정했으며 최종 독립 검증은 99/99였습니다. 그래도 `candidate_only=true`, 공개 토큰 사용과 마스킹 실행은 false였습니다. 검증 통과의 목적어는 **후보 재구성**이었습니다. [E07](../reference/evidence.md#e07)

## 직접 이미지와 더 많은 검증도 자동 해답은 아니었습니다

8월 30일 blind pilot은 100개 방송·270개 전체 페이지의 판독 묶음을 준비했지만 모델 응답 100개는 없었습니다. 별도의 직접 이미지 판독에서는 잘못 읽은 이름에 반복해서 고정되었고, 사용자가 마지막 음절을 지적한 뒤 확대 재판독으로 수정한 기록이 있습니다. 반복 등장한 표기를 보는 것과 독립된 근거를 얻는 것은 달랐습니다. [E08](../reference/evidence.md#e08)

9월 1일 명단 통합은 검사기가 더 중요한 실패 지점이었습니다. 2017년 입력에는 `input_incomplete` 2건과 `blocked` 1건이 있었지만 생성기와 고정 검증기가 함께 이를 놓쳐 `complete`와 입력 문제 0건을 보고했습니다. 57개 시험과 Cycle 00의 통과 뒤에 이 문제가 발견되어 Cycle 01을 중단하고 Cycle 02와 최종 산출물 공개를 하지 않았습니다. [E09](../reference/evidence.md#e09)

9월 초 역할별 명단 작업에는 연도 단위로 다시 통합한 결과도 남아 있습니다. 2006–2019를 다룬 별도 통합은 281개 연도별 인물과 969개 배정, 204개 검토 항목을 기록했습니다. 확정·후보·충돌을 나누어 남기는 구조는 여기에도 필요했습니다. 다만 이 통합본의 모든 행이 뒤의 운영 명단으로 승계됐는지는 연결되지 않습니다. [E35](../reference/evidence.md#e35)

이 구간에서 확인되는 전환은 OCR 표기, 후보 노출, 신원 가설, 실제 이미지 적용을 각각 다른 결과로 다루기 시작했다는 점입니다. 복구 OCR은 기존 관측 옆에 남고, 신원 재구성은 후보 상태를 유지하며, 잘못된 병합 검증은 중단 보고가 됐습니다. 후대의 저장 OCR 처리에서는 이미 확정한 신원과 실패한 기하를 따로 이어받는 문제가 다시 등장합니다. 구체적인 전달과 분기는 [사례 2](02-reading-and-state.md)에서 이어집니다.
