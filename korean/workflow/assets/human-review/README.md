# Human Review · 공개 샘플

[English](../../../../workflow/assets/human-review/README.md)

[앱 HTML](../../../../workflow/assets/human-review/index.html) · [실행 데모](../../demo.md) · [전체 흐름](../../pipeline.md#review-and-repair) · [프로젝트 소개](../../../README.md)

이 앱은 내려받은 저장소를 자기 환경에서 열어보는 **정적 검토 도구 샘플**입니다. 제작자가 직접 호스팅해 운영할 계획은 없습니다. GitHub의 HTML 링크는 소스 보기이므로 아래 로컬 실행 방법을 따릅니다.

기존 Human Review의 화면·검토 흐름·좌표 계산을 재사용한 정적 웹앱입니다. 1994년 1·8쪽, 2003년 5·7·15쪽, 2017년 6·7·13쪽의 **이미 공개용으로 가상화한 입력과 최종 결과**를 연결합니다. 실제 개인정보가 남은 원본, 운영 DB, 과거 방문자의 검토 기록은 포함하지 않습니다. 이름·토큰·적용 영역과 근거는 기존 공개 데모에 연결해 유지했습니다.

## 사용

공유 앱의 조작 문구는 영어입니다. 아래에는 화면의 영문 버튼명과 한국어 뜻을 함께 적었습니다.

1. **Public input / Final output (공개 입력 / 최종 결과)** 버튼으로 전후를 전환합니다. 확대·화면 맞춤·가로 맞춤·회전으로 같은 위치를 확인할 수 있습니다. 검토와 BBOX 입력은 최종 결과에서 합니다.
2. 상태와 이상 유형, 메모를 남깁니다. **Add BBOX (BBOX 추가)** 뒤 드래그하면 영역이 생깁니다. 선택한 영역은 이동·8방향 크기 조절·삭제할 수 있습니다. 좌표는 회전·배율과 무관하게 원래 해상도의 이미지 픽셀 기준입니다.
3. **Needs review (재검토 필요)** 상태에서는 영역을 그린 뒤 클릭 또는 Enter로 확정하고 가상 이름을 입력합니다. 이름 칸의 Enter는 입력을 마치며, 입력칸 밖 Enter는 의견을 저장하고 다음 재검토 페이지로 이동합니다. 빈 이름이 있으면 다음 단계로 넘어가지 않습니다.
4. **Find files (파일 찾기)**에서 연도·파일명·페이지 ID와 상태로 검색합니다. 이전/다음 버튼은 상태를 유지하며 이동합니다. 일반 검토 중 방향키는 이상 없음, Space는 재검토 필요로 저장하고 다음 대상으로 이동합니다. 입력·한글 조합·BBOX 편집 중에는 이 단축키가 상태를 바꾸지 않습니다.
5. **Previous reviews and change history (이전 리뷰 및 변경 이력)**과 **Export JSONL (JSONL 내보내기)**에서 기록을 확인·다운로드합니다. 상태를 이상 없음으로 바꾸며 영역을 지워도 저장 전후 이력은 남습니다. **Public decisions and operations (공개 판단·적용 기록)**은 준비된 데모의 근거이며, 방문자가 새로 작성한 의견과 구별됩니다.

의견과 이력은 브라우저의 IndexedDB, 미확정 BBOX를 포함한 초안은 localStorage에 저장됩니다. 다른 방문자의 브라우저와 공유하거나 서버로 전송하지 않습니다. 같은 기기·브라우저 프로필·사이트 경로의 탭은 같은 기록을 쓰며, 오래된 탭의 덮어쓰기는 버전 검사로 막습니다. 새로고침 후에도 기록이 유지됩니다. 브라우저의 사이트 데이터를 지우거나 비공개 창을 닫으면 기록이 사라질 수 있으므로 보관할 내용은 JSONL로 내려받습니다. 저장을 차단한 환경에서는 오류를 표시합니다.

검토는 의견·좌표 기록입니다. 저장·내보내기로 이미지가 수정되거나, 에이전트가 호출되거나, 실제 아카이브의 승인 상태가 바뀌지 않습니다. 이미지 버전이 바뀌면 이전 의견은 이력에 남고 재검토 대상으로 바뀝니다. 과거 이미지 자체를 별도로 보관하는 기능은 없습니다.

## 로컬에서 실행

앱은 HTML/CSS/JavaScript와 정적 JSON·WebP만 사용합니다. 별도 로그인·운영 DB·API 키·애플리케이션 백엔드가 필요 없고, 외부 라이브러리나 글꼴도 요청하지 않습니다. 의견은 위에서 설명한 브라우저 저장소에만 남습니다.

저장소를 내려받은 뒤 **저장소 루트**에서 다음을 실행합니다. Python 3의 정적 파일 서버를 사용하는 예이며, 다른 정적 파일 서버도 가능합니다.

```sh
python3 -B -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 [로컬 검토 앱](http://127.0.0.1:8000/workflow/assets/human-review/)을 엽니다. 이 명령은 자기 컴퓨터에서 정적 파일만 제공합니다. 사용을 마치면 터미널에서 Ctrl+C로 종료합니다. HTML 파일을 `file://`로 직접 여는 방식은 JSON 로딩·브라우저 저장소 제약 때문에 지원하지 않습니다.

## 정적 환경에 놓기 · 선택 사항

원하는 경우 GitHub Pages 같은 정적 호스팅에도 올릴 수 있습니다. [public-files.txt](../../../../public-files.txt)의 파일만 복사하고 루트·`workflow/`·`history/`·`korean/`의 상대 구조를 유지합니다. 앱 폴더만 복사하면 이웃 `assets/demo/`의 이미지와 문서 링크가 빠집니다. 별도 빌드는 필요 없습니다.

GitHub Pages를 선택한 사용자는 [게시 소스 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 참고할 수 있습니다. 루트의 `.nojekyll`을 함께 두면 Markdown 경로도 그대로 제공됩니다. 앱은 사이트 경로 뒤의 `workflow/assets/human-review/`에서 열며, 저장소가 URL 하위 경로에 있어도 상대 링크를 그대로 사용합니다. 이 설정은 사용자가 선택할 수 있는 실행 예입니다.

GitHub 저장소에서는 Markdown을 문서로 읽고, 단순 정적 서버에서는 Markdown 원문으로 엽니다. 앱과 이미지는 두 경우의 파일 구조를 공유합니다. 실행 주소를 등록하거나 제작자의 서버에 연결하는 절차는 없습니다.

## 유지보수·확인

- `index.html`, `style.css`, `app.js`: 기존 검토 UI를 공개 입력에 맞춰 수정했습니다. 전후 전환·샘플 안내와 공개 근거 연결을 덧붙였습니다.
- `geometry.js`: 기존 좌표 계산을 그대로 사용합니다.
- `browser-store.js`: 서버 저장 인터페이스를 브라우저 저장·검색·충돌 검사·다운로드로 대체합니다. `/api/…` 문자열은 내부 동작 구분이며 HTTP로 요청하지 않습니다.
- `samples.json`: 선택한 8면의 상대 경로, 입력·결과 SHA-256, 공개 적용 영역을 담습니다. 이미지를 중복 복사하거나 원본 DB를 읽지 않습니다.
- `tests/`: 기존 기하·키보드 검사와 정적 하위 경로에서 실제 브라우저 동작을 확인하는 검사입니다. 검사 실행 방법과 확인 결과는 [검증 기록](VERIFICATION.md)에 있습니다.

저장소 루트에서 `python3 -B tools/verify_public.py`를 실행하면 앱·문서·데모를 포함한 명시적 공개 목록, 로컬 링크, 현재 manifest·OCR 입력 해시와 History 기준본을 검사합니다. `workflow/.review-check/`의 브라우저 프로필·다운로드·검사 화면은 배포 대상이 아니며, 공개 목록에 들어가면 검사가 실패합니다. [2026-09-27 통합 검증](VERIFICATION.md#integration-20260927)은 앞선 검증 기록과 구분해 남깁니다.

사진·문서 편집 후의 현재 저장소 확인 결과는 [2026-09-27 공개본 검증 기록](../../../history/reference/publication-check.md)에 있습니다.
