*Protected personal identifiers are synthetic. The Korean scripts, public figures and document structure are retained.*

## 이미 얻은 판단을 유지하며 실행 방식을 고칩니다

시작할 때부터 주어진 근거가 있었습니다. 1994의 제작진과 자기소개 이름 연결, 2003의 전체 이름과 화자 약칭 연결, 지정된 일반인과 보존 인물은 사용자 가이드에서 이어받았습니다. 이번 demo에서는 이를 안전 입력의 실제 등장 위치와 대조했습니다. 2003의 일반인 두 명은 에이전트 판독으로 추가 확인했고, 2017의 손글씨 판독 보완과 학과·입학년도 보존은 사용자의 후속 답변을 반영했습니다. [판단별 출처와 유지 사항](../../workflow/assets/demo/decisions.json)

그 판단이 맞아도 이미지 적용은 실패할 수 있었습니다. 아래는 **2017년 이름 처리 순서를 보정할 당시 보관한 전후 결과**입니다. 위쪽의 `작은우주`와 `맑은수풀`은 손으로 추가한 이름에 대응하고, 아래의 `봄날햇살`과 `산들구름`은 취소된 인쇄 이름에 대응합니다. 서로 다른 인물이라는 연결과 각 토큰은 이미 정해져 있었습니다.

![후속 지움에 잘린 토큰과, 전체 지움 후 배치로 보정한 당시 결과](../../workflow/assets/demo/2017/token-repair.webp)

1. **결과에서 문제를 발견했습니다.** 기존 작업 기록은 에이전트 검토에서 위아래 이름 토큰의 잘림을 확인했다고 남깁니다. 왼쪽에서는 위 토큰의 아랫부분이 끊겨 있습니다.
2. **판단과 실행 실패를 분리했습니다.** 이름 하나를 지우고 토큰을 놓은 뒤 다음 이름을 지우면, 뒤의 지움 영역이 앞서 놓은 토큰을 침범했습니다. 현재 연산의 `erase_sequence`, `erase_box`, `token_box`에서도 그 겹침을 확인할 수 있습니다. 이는 현재 좌표로 원인을 대조한 결과이며, 보관되지 않은 과거 실행 로그를 복원한 것은 아닙니다.
3. **인물 연결과 토큰을 유지했습니다.** 새 이름을 만들거나 두 인물을 합치지 않았습니다. 이미 확정한 분류·토큰을 다시 판단해야 할 문제가 아니었습니다.
4. **적용 순서만 바꿨습니다.** 확정된 이름 영역을 모두 지운 다음, 별도 순회에서 토큰을 배치했습니다. 현재 `replay.py`의 `render_layers()`에도 지움과 배치가 두 순회로 나뉘어 있습니다.
5. **전후 결과와 최종 구현을 연결했습니다.** 오른쪽에는 토큰의 아랫부분이 남습니다. 이 순서를 최종 이미지 생성에 반영했고, 이후 재생도 같은 순서를 사용합니다. [해당 면의 확정 연산](../../workflow/assets/demo/2017/complete/operations.json) · [재생 코드](../../workflow/assets/demo/replay.py) · [보정의 근거 연결](../../workflow/assets/demo/decisions.json)

이 비교 그림은 당시 순서 보정의 기록으로 그대로 유지했습니다. 아래의 현재 결과에는 이번 검토에서 확인한 **취소 상태 표시 누락**도 별도로 고쳤습니다. 과거 전체 아카이브의 보류·보정 작업은 [History](../history/cases/03-review-and-repair.md)의 범위이며, 여기서 다시 실행한 것은 이 세 회차 demo입니다. 이 절은 저장된 이미지·판단·코드를 연결한 설명이고 완전한 대화록이나 시간순 로그가 아닙니다.

`replay.py`는 이렇게 확정된 연산을 안전 입력에 적용하고 결과를 검증합니다. 어떤 표기가 같은 사람인지 판단하거나 검토 의견을 만드는 과정은 재생 코드 밖에서 이뤄졌습니다. 재생이 결정론적이기 때문에, 그때 유지한 판단과 바꾼 실행 방식이 결과에 실제로 반영됐는지를 다시 확인할 수 있습니다.

## 1994 · 작은 이름을 문장과 분리합니다

8쪽 제작진의 가상 이름 `오서윤`과 본문 두 번째 줄의 작은 자기소개 이름은 같은 진행자입니다. 사용자가 제공한 연결을 이어받고, 안전 입력에서 실제 획과 서식선의 위치를 다시 확인했습니다. 두 표기 모두 `푸른나무`로 처리하되, 작은 표기에서는 두 글자씩 나눠 선 왼쪽에 배치했습니다.

![1994년 8쪽의 작은 이름 전후](../../workflow/assets/demo/1994/tiny-name.webp)

**Staff name:** 같은 인물의 이름 크기가 달라져도 토큰은 같습니다. 이름 뒤 `입니다`와 세로 서식선은 남았습니다. [제작진 칸의 같은 토큰](../../workflow/assets/demo/1994/staff.webp)과 [지움·배치 영역](../../workflow/assets/demo/1994/tiny-name-regions.webp)을 함께 볼 수 있습니다. 영역 그림의 청록색은 지움 범위, 주황색은 토큰 배치 범위이며, 실제 처리 이미지와 구별한 설명용 표시입니다.

## 2003 · 같은 화자, 다른 분류

5쪽 제작진의 `이해준 ↔ 해준`, `김소린 ↔ 소린`은 각각 같은 아나운서입니다. 이는 사용자 가이드에서 이월한 연결입니다. 7쪽의 약칭 일곱 곳을 읽어 같은 토큰으로 이어 붙였습니다.

![2003년 5쪽의 제작진 이름](../../workflow/assets/demo/2003/staff.webp)

![2003년 7쪽의 약칭 일곱 곳과 실제 토큰](../../workflow/assets/demo/2003/aliases-seven.webp)

**Short alias:** `해준 → 여름바람`, `소린 → 새벽노을`. 제작진은 한 줄, 화자 표지는 2+2 배치입니다. 안내 목록을 읽고 만든 연결을 독립 자동탐지의 성과로 집계하지 않았습니다.

여기서 재사용한 것은 전체 이름과 약칭의 **인물 연결**이고, 이번 입력에서 확인한 것은 그 약칭이 실제로 나온 일곱 위치입니다. 연결은 [판단 기록](../../workflow/assets/demo/decisions.json)에, 각 지움 영역과 같은 토큰의 반복 적용은 [2003 연산 기록](../../workflow/assets/demo/2003/complete/operations.json)의 7쪽에 남아 있습니다.

기사 인물은 다른 결정으로 보냈습니다. 사용자가 지정한 후보자 네 명과 이번 판독에서 추가 확인한 일반인 두 명은 입력에서 가상화한 뒤, 최종 결과에서 흰색과 얇은 검은 테두리로 가렸습니다. 방송국 스태프 토큰을 주지 않았습니다.

[판단 기록의 `ordinary_people`](../../workflow/assets/demo/decisions.json)은 네 명의 지정과 두 명의 추가 판독을 구분합니다. 이를 합친 일반인 여섯 명의 11회 등장이 `class: private`인 연산으로 이어졌습니다. 기존 지정만 재생한 결과와 이번 판독으로 보탠 결정을 섞어 설명하지 않았습니다.

![2003년 기사 인물의 가상 이름과 흰색 마스크](../../workflow/assets/demo/2003/private-people.webp)

**Private person / Keep:** 15쪽의 `권영길 의원`은 사용자 지정 보존 대상이라 그대로 남습니다. [같은 위치의 보존 전후](../../workflow/assets/demo/2003/keep.webp). 기사에 등장했다는 사실만으로 인물을 모두 같은 분류로 보내지 않았습니다. [판독과 상태의 관계](../history/cases/02-reading-and-state.md)

## 2017 · 수정된 원고를 수정된 채 읽습니다

6쪽에는 인쇄된 진행자 이름을 취소하고 다른 이름을 위에 쓴 흔적이 있습니다. `고나린`과 수기 `김도현`, `배서우`와 수기 `한예솔`은 각각 **다른 인물**입니다. 본문에 남은 한 글자 화자 표지 `고`, `배`도 원래 인물의 표기로 기록했습니다. 수정 후의 진행 역할을 근거로 모두 한 사람으로 합치지 않았습니다.

![2017년 인쇄 이름과 수기 대체 이름의 처리](../../workflow/assets/demo/2017/replacement-names.webp)

**Correction:** 위아래 두 이름에 서로 다른 토큰이 남습니다. [인물 구분 기록](../../workflow/assets/demo/decisions.json)의 `replacement_examples`와 [2017 연산](../../workflow/assets/demo/2017/complete/operations.json)을 연결하면, 취소된 인쇄 이름과 새 손글씨에 서로 다른 토큰을 준 이유를 확인할 수 있습니다. 취소 상태는 입력 원고의 수정 관계이며 이번 demo의 검수 표시가 아닙니다. [지움·토큰 영역 보기](../../workflow/assets/demo/2017/replacement-names-regions.webp)

<a id="cancelled-token-repair"></a>

이번 검토에서는 `input_cancelled: true`가 있어도 재생 코드가 이를 그리지 않는 누락을 확인했습니다. **인물·토큰·한 줄/2+2 배치와 안전 입력은 유지**하고, 취소된 토큰의 각 줄 안에 얇은 1px 직선을 새로 그렸습니다. 원래 이름 획을 되살리지 않습니다. 선은 토큰 배치 뒤 이름 레이어와 그 마스크에 함께 반영해 합성에서도 남게 했습니다. 한 곳은 인접 토큰과 겹치지 않도록 선의 시작만 안쪽으로 제한했습니다. 위 비교 그림의 최종 결과와 2017년 7면·20곳을 갱신했습니다. [선 좌표·변경 범위·재생·OCR 검증](../../workflow/assets/demo/revision-verification.json) · [구현의 `cancellation_lines()`](../../workflow/assets/demo/replay.py)

7쪽의 취소된 옛 번호와 새 번호도 둘 다 이미지에 남아 있습니다. 안전 입력에서는 `000-0000-0001`과 `000-0000-0002`라는 서로 다른 더미값을 썼고, 보호 단계에서 두 표기를 모두 가렸습니다.

![구번호와 신번호의 실제 처리](../../workflow/assets/demo/2017/contact.webp)

**Contact:** “현재 사용할 번호”를 읽는 판단과 “이미지에 남은 번호 영역”을 가리는 판단은 다릅니다. 12쪽의 부분 수정은 같은 접두부와 손으로 바뀐 뒷자리를 연결해 처리했습니다. [부분 번호 수정의 전후](../../workflow/assets/demo/2017/contact-suffix.webp). 겹친 마스크의 내부에는 테두리를 남기지 않는 기존 [연락처 합집합 연산](../../history/historical/contacts/paint_union.py)을 실제로 사용했습니다.

13쪽의 이름·여백 수정도 처리했습니다. 사용자가 판독을 보완한 손글씨는 그 답변과 위치를 연결해 반영했습니다. **학과와 입학년도는 마스킹 대상이 아니라는 후속 지시를 적용**했고, 아래 학적 정보 영역은 마스킹에서 제외했습니다.

이 지시는 이름 판독 결과를 버리는 변경이 아니었습니다. 이름에 대한 지움·토큰 연산은 유지하면서 비인명 학적 정보를 처리 범위에서 제외했습니다. [보존 판단](../../workflow/assets/demo/decisions.json)의 `keep_examples`와 [13쪽 연산](../../workflow/assets/demo/2017/complete/operations.json)을 함께 보면 이 경계를 확인할 수 있습니다. 이번 취소선 보정도 그 지움 범위를 넓히지 않았습니다.

![이름과 학과·입학년도 처리 경계](../../workflow/assets/demo/2017/credits.webp)

### 유지한 토큰 배치 규칙

사용자가 지정한 `TOKEN_SIZE_RULES_20260925.md`도 반영했습니다. 세로 화자는 2+2·17px, 본문은 한 줄·22px를 기본으로 하며 좁으면 2+2·14–17px를 씁니다. 제작진은 회차 안에서 같은 크기를 유지했고, 낮고 촘촘한 2003·2017 제작진 칸에는 허용된 16px를 적용했습니다. 기준 높이 1,684px에서 현재 논리면 높이로 비례 확대했으며 **토큰 글자를 가로로 압축하지 않았습니다**. 원 규칙의 연도 범위 밖인 1994에는 같은 세로 역할 기준을 데모 확장으로 적용했습니다. ### 독립된 결과를 영역으로 합칩니다

## 최종 이미지에서 다시 읽은 텍스트

최종 WebP를 Apple Vision이 실제로 다시 읽었습니다. 이전 OCR의 이름만 치환하지 않았고, 아래 원시 결과를 보기 좋게 고치지도 않았습니다.

![최종 OCR이 실제로 읽은 번호 처리 장면](../../workflow/assets/demo/2017/final-ocr-crop.webp)

```text
둘째,
문자를 보내주세요.
어때요? 정말 간단하죠?
```

이미지에는 남아 있는 `로`를 OCR은 누락했습니다. 이 한계도 원시 결과에 그대로 남겼습니다. [같은 crop의 원시 OCR·좌표·입력 해시](../../workflow/assets/demo/2017/final-ocr-excerpt.json) · [전체 최종 OCR](../../workflow/assets/demo/2017/final-ocr.json). 53면 모두 OCR의 `sourceSHA256`과 실제 최종 WebP가 일치합니다. [최종 이미지와 OCR의 연결](pipeline.md#final-link)

## 전체 회차와 실행 기록

전체 회차의 WebP 114개는 **품질 90**으로 압축하여 직전 무손실 WebP보다 **65.5%** 가볍게 만들었습니다. 해상도는 유지했습니다. 본문 비교 그림 44개는 무손실 WebP입니다. 압축된 안전 입력에서 동일한 확정 연산을 다시 실행하고, 최종 WebP의 OCR도 새로 읽었습니다. [변환 검증](../../workflow/assets/demo/format-conversion.json)

연락처는 보존된 원 코드를, 합성은 원 코드의 사각형 연산과 별도의 픽셀 대조를, OCR은 보존된 Swift 구현을 실행했습니다. 결재란의 Pillow 렌더링, 안전 입력 연결과 확정 토큰 배치는 이번 데모용 어댑터입니다. 과거부터 존재한 통합 실행기로 설명하지 않습니다. [보존 코드의 범위](../history/historical/README.md)

원본 PDF·History·기존 작업 설명은 읽기 전용으로 유지했습니다. 준비와 합성의 영역 처리에서는 허용 범위 밖 픽셀 변경이 **0**입니다. 이 검사는 배포용 손실 인코딩 전 기준이며, 품질 90 압축은 전체 면의 픽셀에 영향을 줍니다. 공개 재실행 코드는 53면의 최종 WebP 해시를 다시 재현했습니다. 이는 파일 재현성과 이미지·OCR 연결을 확인한 결과입니다. 판독 정확도와 승인·배포에 관한 [공개 범위와 한계](../README.md#공개-범위와-남은-한계)는 루트 소개에 모았습니다.

## 공개 가능한 입력을 준비한 과정

이 절은 본문의 판단·보호 처리에 들어가기 전 **demo-source-safe 제작**에 관한 기록입니다. 기존 가상 이름·연락처와 전후 이미지는 유지했으며, 이번 취소선 보정 때문에 안전 입력을 바꾸지는 않았습니다.

입력 준비 당시 사용자는 손글씨 패치가 원고와 닮지 않았다고 지적했습니다. 요청한 GPT-6 Luna / max 서브에이전트에 실제 손글씨의 확대 crop을 참조로 전달했고, 작은 잉크 패치를 생성해 필요한 영역에만 합성했습니다. 그 과정에서 사용한 도구는 ImageGen이며, 도구 내부 모델 이름을 Luna로 단정하지 않습니다. 원본 crop과 실명 대응표는 공개하지 않았습니다.

이어 받은 취소선·숫자 크기 지적에 따라 원래 글자 획이 섞일 수 있는 취소선 띠 복사를 제거하고, 가상 글자 위에 새 취소선 패치를 얹었습니다. 숫자를 위치 상자에 억지로 늘이던 처리도 제거했습니다. 아래는 실제 보관한 안전 입력 두 버전의 같은 crop입니다. 이는 **입력의 가상 번호 비율 보정**이며, 본문의 토큰 잘림·최종 취소 상태 보정과 다른 작업입니다.
